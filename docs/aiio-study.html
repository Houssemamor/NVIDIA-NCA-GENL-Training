Domain 1: Essential AI Knowledge

AI, Machine Learning, and Deep Learning

  • Artificial intelligence: The broad field of building systems that perform tasks associated with human intelligence.
  • Machine learning: A subset of AI in which models learn patterns from data instead of following only hand-written rules.
  • Deep learning: A subset of machine learning that uses multi-layer neural networks to learn hierarchical features.

Training vs Inference

PhaseMain GoalResource Pattern
TrainingLearn model weights from dataForward pass, loss, backpropagation, activation storage, large batches, multi-node scaling
InferenceServe predictions with low latency and high throughputSmaller batches, KV cache for LLMs, batching, quantization, model optimization

Transformer Pipeline (High Level)

Tokens -> Embeddings + Positional Encoding -> Multi-Head Attention -> Add & Norm -> Feed-Forward -> Add & Norm -> Output

Self-attention compares each token with the others: Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V. Multi-head attention lets the model learn several relationship types at once.

Scaling Laws and Memory Math

  • Chinchilla-style scaling: Model quality depends strongly on training compute and the number of training tokens, scaled together.
  • Weight memory: parameters x bytes per parameter. A 70B model in FP16 needs about 70B x 2 bytes = 140 GB just for weights.
  • Practical memory: Add activations, KV cache, gradients, optimizer state, and runtime overhead. Training needs substantially more than inference.
  • Activation memory: Training retains intermediate activations for backpropagation; this often dominates memory for large transformer training jobs.

Domain 2: AI Infrastructure

GPU and Node Architecture

  • Streaming multiprocessors (SMs): Execute CUDA threads and warps.
  • Tensor Cores: Accelerate matrix multiply-accumulate operations used by deep learning.
  • HBM: High-bandwidth memory close to the GPU; capacity and bandwidth are primary model-fit constraints.
  • NVLink and NVSwitch: High-bandwidth GPU-to-GPU fabric for scale-up inside a node or rack.
  • DGX H100: Eight H100 GPUs with four NVSwitch chips and 640 GB of total HBM3 memory.

Scale-Up vs Scale-Out

ModelScopeInterconnectTrade-off
Scale-upGPUs inside one node or rackNVLink / NVSwitchVery high bandwidth and low latency; limited domain size
Scale-outMultiple nodesInfiniBand or EthernetHorizontal growth and fault tolerance; higher communication latency

AI Networking

  • InfiniBand data rates: HDR 200 Gbps, NDR 400 Gbps, XDR 800 Gbps per port.
  • RoCEv2: RDMA over Converged Ethernet. Requires careful congestion control, lossless configuration, and telemetry to approach InfiniBand latency.
  • Spectrum-X: NVIDIA Ethernet platform for AI that combines Spectrum-X switches with BlueField-3 SuperNICs or DPUs, adaptive routing, and congestion control.
  • SHARP: In-network aggregation and reduction for InfiniBand, allowing collective operations such as all-reduce to run inside the switch fabric.
  • GPUDirect RDMA: Lets a network adapter transfer data directly to or from GPU memory, avoiding a host-memory copy.
  • East-west traffic: GPU-to-GPU training traffic, latency-sensitive, often RDMA. North-south traffic: user and management traffic, often standard TCP.
  • Job completion time is the outcome metric for an AI network; bandwidth and latency are diagnostic measures.

DPUs

  • BlueField-3: 400 Gb/s DPU used for networking, storage, security, and infrastructure offload.
  • Isolation: Infrastructure services can run in a separate DPU domain, remaining enforceable if the host operating system is compromised.
  • DOCA: SDK and runtime for building DPU-accelerated services.

Storage

  • Parallel distributed file systems such as Lustre and WEKA provide the aggregate bandwidth and concurrent access needed by many training workers.
  • Local NVMe is fast but isolated to one node; it is useful for caching and scratch data.
  • Object storage is durable and cheap for datasets and checkpoints but usually adds latency for active training reads.

Power and Cooling

  • PUE = total facility power / IT equipment power. A PUE of 1.15 means facility power is 15% higher than IT power, not that 15% is all cooling.
  • Air cooling becomes impractical for many GPU-dense racks above roughly 40-50 kW; direct liquid cooling is commonly used at that density.
  • Immersion cooling is an alternative for very high density but is not the only valid option.
  • BMC: Baseboard management controller provides out-of-band power, console, sensor, and firmware management even when the host OS is down.

Deployment Models

  • On-premises DGX + InfiniBand: Strong choice when data must remain under organizational control and maximum training performance is required.
  • Public cloud: Fast capacity and elasticity, but data residency, egress, and cost must be evaluated.
  • NVIDIA-Certified Systems: Partner-built servers validated against NVIDIA's baseline for performance, security, and scale.

Domain 3: AI Operations

GPU Monitoring Pipeline

DCGM -> DCGM Exporter -> Prometheus -> Grafana
  • DCGM: NVIDIA Data Center GPU Manager. Collects telemetry, health, diagnostics, and policy data.
  • DCGM Exporter: Exposes DCGM metrics in Prometheus format.
  • Key metrics: GPU utilization, memory utilization, temperature, power, ECC errors, XID errors, throttle reasons, NVLink errors, PCIe replay.
  • MFU: Model FLOP Utilization. High GPU utilization with low MFU often means small kernels, launch overhead, or poor Tensor Core use rather than useful math.

Orchestration and Scheduling

  • NVIDIA Device Plugin: Exposes GPUs to Kubernetes as schedulable resources such as nvidia.com/gpu.
  • NVIDIA GPU Operator: Automates drivers, container toolkit, device plugin, GPU feature discovery, and monitoring components on Kubernetes.
  • Gang scheduling: Allocates all workers of a distributed job together, preventing partial allocation deadlocks.
  • Run:ai: Kubernetes-native GPU scheduling with quotas, fractional allocation, and preemption.
  • Slurm: Common HPC batch scheduler; --gres=gpu:4 requests four GPUs.
  • Base Command Platform: NVIDIA's management layer for DGX clusters, including workload management and software lifecycle.

Virtualization

MethodIsolationTypical Use
MIGHardware-level partitions with dedicated compute, memory, and cacheMulti-tenant sharing with predictable performance; up to 7 instances on H100

Reliability and Performance

  • ECC single-bit errors (SBE): Correctable; track trends but do not ignore repeated events.
  • ECC double-bit errors (DBE): Uncorrectable; investigate immediately and consider page retirement or GPU replacement.
  • Thermal throttling: Many data center GPUs reduce clocks in the mid-80s Celsius to protect hardware; check the specific model's limits and throttle reasons.
  • NCCL all-reduce: Gradient synchronization across GPUs. Slow all-reduce points to fabric bandwidth, latency, or congestion problems.
  • 100 Gbps Ethernet is undersized for large distributed training fabrics; InfiniBand or 400G+ Ethernet is the usual upgrade path.

Exam Traps

  • GPU utilization is not performance. A GPU can be busy with small kernels while useful FLOP utilization stays low.
  • PUE is a ratio, not a cooling percentage. The overhead includes cooling, power distribution, and other facility loads.
  • MIG is not the same as time-slicing. MIG partitions hardware resources; time-slicing shares a GPU without full isolation.
  • vGPU is licensed software. It is not included automatically with the GPU hardware.
  • Scale-up is not scale-out. NVLink is the scale-up fabric; InfiniBand or Ethernet is the scale-out fabric.
  • East-west is not north-south. Training traffic is east-west; user and management traffic is north-south.
  • Free access is not a license. Third-party practice content may be copyrighted even when it is free to read.
  • Read the qualifier. Words such as "primary", "best", "most likely", and "minimum" change the intended answer.

Exam Time Management

  • First pass (30-35 min): Answer confident questions, mark uncertain ones, and keep moving.
  • Second pass (20-25 min): Review marked questions and use elimination.
  • Final check (5 min): Confirm every question has an answer and revisit flagged items.
Tip: The exam is 50 questions in 60 minutes. Do not spend more than about 90 seconds on any single question on the first pass.
